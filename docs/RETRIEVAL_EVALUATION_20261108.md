## 发现的问题

`campus 食堂 lunch expenses` 的目标是 `校园食堂午餐`，但原混合排序把 `Grab ride to campus` 放在第一。

- 午餐相似度：0.73494；打车相似度：0.49562。
- 原 SQL 和评测脚本将任何英文字面命中都提升为“精确标识”，普通词 campus 因此获得额外优先级。
- SQL 还存在融合分数相同时直接按 UUID 排序的问题，可能让较低语义相关度的记录排前。

修正方式：保留所有原有关键词候选及其 RRF 权重，但只有完整匹配的缩写/编号（例如 TAI、CS401、TAI-101，或原文中全大写的缩写）进入保护层。纯数字、普通词 campus、单词 detail 内部的 tai 都不进入保护层。融合分数并列时依次比较语义相似度、关键词命中数和 ID。

SQL、评测脚本规则已同步；对已执行原迁移的项目提供独立增量：`database/migrations/20261109_hybrid_retrieval_ranking_fix.sql`。它只更新判定与检索函数，不修改业务数据或重建向量；新安装直接使用最新版主迁移也包含修正。

修正后本地 `node --test` **293/293 通过**；新增 3 项回归覆盖 SQL/JS 判定一致、UUID 顺序不利时的账单排序，以及 9 个真实相似度样例的离线重排。本轮仅修改数据库查询与评测脚本，未改动前端；未执行远程 SQL 或部署，也未再次调用 Cloudflare。
