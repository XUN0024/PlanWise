# 笔记标签：部署与验收

## 执行流程

1. 已有笔记数据库先完成 `20261103_notes_model.sql`。
2. 在当前 Supabase 项目的 SQL Editor 执行 `20261105_note_tags.sql` 全文。
3. 执行 `20261105_note_tags_verify.sql`，三个表的 RLS 应为 true，权限结果为
   `false / false / false / true / true`，重复标签查询为空。
4. 更新/刷新客户端。若页面此前提示数据库未配置，可点击“重新读取标签”。

这里不需要重新执行 `fresh_setup.sql`，也不需要修改 Storage 或 OAuth 设置。
本地实现及 PostgreSQL 测试不会自动修改你的线上 Supabase 数据库。

## 数据与迁移

- `tags` 保存账号标签库，包括 UUID、名称、六种预设颜色和版本时间。
- `note_tags` 保存多对多关联，复合外键确保笔记和标签拥有相同 user_id。
- 同一账号按去首尾空白、忽略大小写的名称唯一；不同账号可使用相同名称。
- 新名称 1–100 个 Unicode 字符。数据库负责最终判重；UI 先给出重复提示。
- 旧 `notes.tags` 自动去空值、空白和重复，按账号迁移；名称超长则整笔迁移
  回滚并给出错误，需核对旧数据后重试，不会静默截断已有标签。
- `note_tag_migrations` 记录一次性迁移。脚本可重复执行，已移除的关联、
  已删除或重命名的标签不会从旧字段复活。不要删除迁移标记。
- `notes.tags` 暂时保留为历史数据；新客户端从独立标签表读取，不再读写此列。
  旧版客户端写此列不会更新新标签库，部署后请刷新所有旧客户端。

## 操作方式

- 笔记标题下/正文前点击“添加标签”，搜索、选择已有标签，或创建并关联。
  标签上的 × 仅移除当前笔记关联。新笔记首次保存成功后才能添加标签。
- 侧栏“管理标签”打开真实标签库，可新增、修改名称/颜色、删除。
  删除前显示关联笔记数，删除只清理标签及关联；笔记与附件保留。
- 点击侧栏标签按 ID 精确筛选；支持与关键词、原有 #tag 搜索叠加。
  使用数量统计当前账号全部笔记，零引用标签也保留在标签库中。
- 标签操作立即保存，正文继续 800ms 自动保存。标签请求期间可继续输入正文；
  正文保存等待标签请求结束，双方不会覆盖彼此的数据。标签关联不修改
  notes.updated_at，重命名也不需要逐篇写入笔记。
- 失败保留输入和上次确认状态。重命名/全局删除使用标签 updated_at 检查版本；
  冲突后重新读取标签，核对当前值再编辑。刷新标签不会重新加载或丢弃正文草稿。
- 当前页面操作后立即更新；其他设备/窗口通过重新读取标签或刷新获取最新值。

## 线上验收

1. 两篇笔记关联同一标签；刷新，关联仍保留。移除一篇的关联，另一篇保留。
2. 创建零使用标签，侧栏/管理弹窗显示 0；关联后变为 1。
3. 全局重命名及改色，两篇笔记均更新；过滤继续使用原标签 ID。
4. 删除全局标签，确认显示影响数量；确认后所有关联清理，笔记/附件仍在。
5. 使用中文、含空格名称、大小写重复名称检查搜索、验证和重复处理。
6. 正文输入后立即修改标签，在请求期间继续打字；停止输入后自动保存，刷新
   同时保留富文本正文和新标签。断网失败应保留输入，不显示虚假成功。
7. 两个账号通过客户端及直接 API 验证隔离：无法查看、修改对方标签，不能将
   自己标签关联到对方笔记，也不能将对方标签关联到自己笔记。
8. 两窗口编辑同一标签，旧版本提交须报冲突。重复执行迁移脚本后已删除标签
   及关联不会复活。删除笔记后引用数减少，标签仍留在库中。

本地测试包含 PGlite 的真实 PostgreSQL 迁移、RLS、RPC、约束和级联行为，
React/jsdom 标签选择及管理交互，以及页面自动保存协调测试。
线上 Supabase 配置、真实浏览器/Electron 布局仍需按上述步骤验收。
