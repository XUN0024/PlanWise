# PW AI Tasks Assistant 第一版

更新：2026-11-08，Asia/Kuala_Lumpur。

后续更新：界面已并入 [统一聊天与参考范围](./UNIFIED_AI_SETUP.md)，不再使用独立 Tasks Tab。本文保留任务底层查询、权限与验收规则；当前从 PW AI 的“今日重点建议”或“＋参考 → 我的任务”使用，具体任务可从页面的 PW AI 按钮带入。

## 已实现范围

本轮按用户截图实施“今日重点建议”和“任务拆解”，新增独立 Tasks Assistant Tab。定位：帮用户看清手上的事情、决定先做什么，并把大任务拆成可以开始的步骤。

- 在 Tasks 页面打开 PW AI 默认进入任务助手；其他页面也可切换到此 Tab。
- 全部任务：点击“今日重点建议”直接发送一次请求，推荐最多 3 项未完成任务，说明理由并给出每项第一步。不足 3 项时返回实际数量；没有未完成任务时显示空状态。
- 指定任务：搜索并选择已保存任务，点击“拆解这项任务”，读取描述及已有子任务。模型应复用未完成步骤、保留已完成状态，区分已有步骤和新增建议；结果仅为预览，不写入任务表。已完成主任务也可选择，不能误说成尚未完成。
- 选择器显示最多 30 个结果，支持搜索、250ms 延迟查询、取消旧请求、空状态、失败重试及账号隔离；有更多结果时提示缩小搜索范围。
- 可在当前范围继续提问；普通对话、笔记、支出、全部任务及每项指定任务的草稿和会话分别保存在当前账号内存，刷新、退出或换账号后不保留。
- 回答显示核对后的数量、子任务进度和来源。来源打开 `/tasks?task=<id>`，按当前账号重新读取完整记录，以只读卡片展示，不覆盖编辑草稿。

待实施：完整任务查询/筛选工具、跨任务进度分析、确认后将拆解写入子任务、统一 RAG 入口。第一版不创建、修改、完成或删除业务记录，也不读取笔记、支出、文件或互联网。

## 数据口径

- `get_task_insights(uuid,date)` 使用一个数据库快照读取当前账号任务及关联子任务。主任务完成状态与子任务完成数量分别统计，不能互相推断。
- 今日重点：提醒为今天的未完成任务 → 提醒日期已过去的任务 → 其他任务；组内按 High / Medium / Low、较早提醒日期、较早创建时间及 ID 排序，取前 3 项。未设优先级按 Medium 处理。
- 这是第一版透明的推荐规则；模型解释并提供第一步，不自由重排全库任务。总体数量覆盖所有任务，focus 上下文只有最多 3 项推荐。
- `reminder_date/time` 是提醒，不是截止时间。过去的提醒不等于逾期；不虚构截止日期、依赖、可用时间或预计耗时。今天由服务端按马来西亚日期确定。
- 全部任务概览：每项标题最多 300 字符，描述最多 1,500 字符，最多 10 个子任务；省略/截断均有标记和界面提示。
- 指定任务：标题和每项子任务标题最多 300 字符，描述最多 8,000 字符，最多 50 个子任务，重复设置文本最多 100 字符。超出时拒绝生成并提示精简，避免遗漏已有步骤后声称“没有重复”。
- 拆解的语义质量仍需真实模型验收，不能保证每次都无重复。界面没有直接将预览写入数据库的操作。

## 权限、缓存与来源

客户端只发送消息和 `context: {type:'tasks', action:'focus'|'breakdown', taskId:null|uuid}`。focus 必须使用全部任务，breakdown 必须指定一项任务；不能传任意 SQL、其他用户 ID 或伪造任务内容。

Edge Function 验证登录，用用户 JWT + Supabase 公钥调用 RPC。函数为 SECURITY INVOKER，使用 auth.uid()、显式 owner 条件及现有 tasks/subtasks RLS。管理凭据只用于 AI 额度登记，不用于越权读取任务。

前后端核对报告结构、统计约束、范围和来源。任务文本只作为不可信资料，不能覆盖 system 规则；模型没有任务写入工具，来源从真实记录构造，不采用模型生成的链接。

任务表没有 updated_at，因此用主任务全部字段及全部子任务内容生成版本指纹；全部任务范围也涵盖未入选推荐的记录。修改子任务、完成状态、描述、提醒或删除任务均会改变指纹。重试先检查最新权限和内容；变化时提示 AI_TASK_CHANGED，点击重试生成新请求。

沿用既有额度、取消、错误处理和回复缓存。任务回复上限为 1,536 completion tokens，其他模式保持原上限。请求计数不代表供应商实际用量。

## 验收

1. 用至少 4 项未完成任务，混合提醒日期、优先级、已完成及未完成子任务；再准备一项已完成主任务。推荐最多 3 项真实未完成任务，各有理由和第一步。
2. 选择“准备项目汇报”等任务测试拆解，核对利用已有步骤、区分完成状态及新增建议；数据库内容和记录数量应保持不变。
3. 验证无任务、全部完成、仅 1–2 项、信息不足及超长内容。不能把提醒称作截止逾期，不能补造任务。
4. 编辑/删除任务或子任务后重新提问应使用最新资料；成功请求重试不重复推理。
5. 来源可打开搜索隐藏或已完成任务；删除或无权限来源显示错误，编辑草稿保留。
6. 两个账号验证选择器、指定 UUID、来源及缓存隔离；退出或换账号后迟到的回复不能出现。

本轮未执行线上 SQL、未部署函数、未调用真实模型。实际解释与拆解质量、延迟仍待上线验收。
